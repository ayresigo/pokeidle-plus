## Directory Purposes

**`apps/central-api/`:**
- Purpose: Multi-tenant central backend; the only component that touches Postgres.
- Contains: Feature folders under `src/` each exposing `register<Feature>Routes(app, prisma)`; Prisma schema/migrations; admin seed.
- Key files: `src/app.ts`, `src/server.ts`, `src/auth/service.ts`, `src/auth/guard.ts`, `src/accounts/routes.ts`, `src/crypto/secrets.ts`, `prisma/schema.prisma`, `prisma/seed.ts`, `prisma.config.ts`

**`apps/control-plane/`:**
- Purpose: Local orchestrator and backend-for-frontend for the panel.
- Contains: Feature folders under `src/` exposing `register<Feature>Routes(app, deps)`; long-lived services (`SessionStore`, `Supervisor`, `UpdateManager`, `DockerOrchestrator`) wired in `src/app.ts`.
- Key files: `src/app.ts`, `src/server.ts`, `src/orchestrator/types.ts`, `src/orchestrator/orchestrator.ts`, `src/orchestrator/recriar.ts`, `src/supervisor/supervisor.ts`, `src/update/manager.ts`, `src/session/store.ts`, `src/auth/guard.ts`, `src/central/repasse.ts`, `src/workers/routes.ts`, `src/stream/routes.ts`

**`apps/web/`:**
- Purpose: Browser UI; every data call goes through `/cp/*`.
- Contains: App Router pages (thin wrappers that render one component), client components, framework-free helpers in `lib/`.
- Key files: `app/cp/[...path]/route.ts`, `app/(painel)/layout.tsx`, `lib/api.ts`, `lib/status.ts`, `lib/conta.ts`, `lib/update.ts`, `lib/usuario.ts`, `lib/sse.ts`, `lib/sessao.ts`, `components/Dashboard.tsx`, `components/AccountForm.tsx`, `components/UpdatePanel.tsx`, `components/UsersPanel.tsx`

**`packages/worker/`:**
- Purpose: One process per PokeIdle account.
- Contains: `auth/` (login strategies), `game/` (protocol + bot behaviour), top-level infra modules.
- Key files: `src/index.ts`, `src/config.ts`, `src/health.ts`, `src/http.ts`, `src/auth/provider.ts`, `src/auth/refresh.ts`, `src/auth/solver.ts`, `src/game/client.ts`, `src/game/loop.ts`, `GAME.md`

**`packages/updater/`:**
- Purpose: Self-update of the compose-managed containers.
- Contains: Flat `src/` with orchestration, pure planner, dockerode adapter, test fixtures.
- Key files: `src/main.ts`, `src/atualizar.ts`, `src/recriacao.ts`, `src/docker.ts`, `src/fixtures.ts`

**`e2e/`:**
- Purpose: Full-stack smoke (login → create account → start → logs → needs-login → stop → update notice) against locally built `:e2e` images; never talks to the real game or GHCR.
- Contains: Playwright config/spec, Docker helper scripts, fake game server.
- Key files: `smoke.spec.ts`, `docker.ts`, `global-setup.ts`, `docker-compose.e2e.yml`, `fake-game/server.ts`, `fake-game/token.ts`, `ambiente.ts`

**`docker/`:**
- Purpose: Image build definitions (build context is the repo root).
- Contains: `Dockerfile.central-api`, `Dockerfile.control-plane`, `Dockerfile.web`, `Dockerfile.worker`, `Dockerfile.updater` (all `node:22-slim` multi-stage: `deps` → `build` → `runtime`, `ARG VERSION` → `ENV APP_VERSION`), `docker-compose.dev.yml` (local Postgres `mpw_dev` on 5432).
- Key files: as listed. The fake-game Dockerfile lives at `e2e/fake-game/Dockerfile`.

**`k8s/base/`:**
- Purpose: Official central deployment on cluster `tcgreaper`.
- Contains: `kustomization.yaml` (namespace `pokeidle`, image tag pin `newTag`), `namespace.yaml`, `central-api.yaml` (Deployment + Service + NetworkPolicy allowing Traefik only), `ingress.yaml` (host `pokeidle.ayresigo.dev`, cert-manager `letsencrypt-prod`), `postgres-backup-cronjob.yaml` (daily `pg_dump`), `secrets.example.yaml` (template for Secret `pokeidle-secrets`, not applied by kustomize).

**`.github/workflows/`:**
- Purpose: CI and release.
- Contains: `ci.yml` (push to main / PR / `workflow_call`: Postgres 16 service, prisma generate + migrate deploy, `tsc --noEmit` on central-api/control-plane/worker/updater, `pnpm -r test`, web lint + build), `release.yml` (tag `v*`: semver/channel → ci → matrix build-push of 5 images → register release in central → move `:stable`/`:beta`).

**`docs/plans/`:**
- Purpose: Approved design and task-by-task implementation plan.
- Key files: `2026-10-11-multiacc-pokeidle-design.md`, `2026-10-11-multiacc-pokeidle-plan.md`

## Naming Conventions

**Files:**
- Backend source: lowercase single-word or kebab-case `.ts` named by role inside a feature folder: `routes.ts`, `service.ts`, `guard.ts`, `store.ts`, `manager.ts`, `orchestrator.ts`, `types.ts` (e.g. `apps/control-plane/src/update/manager.ts`). Portuguese names are used for helpers: `repasse.ts`, `recriar.ts`, `atualizar.ts`, `recriacao.ts`.
- Tests: `<name>.test.ts` next to the subject; `<name>.unit.test.ts` when a Docker-integration test with the same base name exists. Feature-level tests may be named after the feature (`apps/central-api/src/accounts/accounts.test.ts`).
- React components: PascalCase `.tsx` in `apps/web/components/` (`AccountForm.tsx`, `UpdatePanel.tsx`).
- Next.js routes: framework names (`page.tsx`, `layout.tsx`, `route.ts`); route groups in parentheses (`(painel)`), dynamic segments in brackets (`[id]`, `[...path]`).
- Web helpers: lowercase Portuguese/English nouns in `apps/web/lib/` (`conta.ts`, `usuario.ts`, `sessao.ts`, `status.ts`, `update.ts`, `sse.ts`, `api.ts`).
- Dockerfiles: `docker/Dockerfile.<image-name>` where `<image-name>` matches the workspace package and the GHCR image suffix `mpw-<image-name>`.
- Prisma migrations: `prisma/migrations/<YYYYMMDDHHMMSS>_<snake_description>/migration.sql`.
- Plans/docs: `docs/plans/<YYYY-MM-DD>-<slug>-<design|plan>.md`.

**Directories:**
- Deployable services in `apps/` (have HTTP servers users/other services call); container-only processes in `packages/`.
- Inside backend `src/`: one folder per feature/domain (lowercase, plural for resources: `accounts/`, `users/`, `workers/`, `releases/`; singular for capabilities: `auth/`, `session/`, `update/`, `stream/`, `proxy/`, `crypto/`).
- Test fixtures: `__fixtures__/` inside the module folder.

**Runtime names:**
- Containers: `mpw-worker-<accountId>`, `mpw-updater`; compose projects `mpw`, `mpw-central`, `mpw-e2e`; network `mpw`; volume `mpw-data` (seen as `mpw_mpw-data`).
- Images: `ghcr.io/ayresigo/mpw-{web,control-plane,worker,updater,central-api}` (+ `mpw-fake-game:e2e` locally).

## Where to Add New Code

**New central API endpoint/resource:**
- Primary code: `apps/central-api/src/<feature>/routes.ts` exporting `register<Feature>Routes(app: FastifyInstance, prisma: PrismaClient)`; register it in `apps/central-api/src/app.ts`.
- Auth: wrap in `app.register(async (escopo) => { escopo.addHook("preHandler", requireAuth); ... })`; add `{ preHandler: requireAdmin }` for admin routes; always filter by `userId: request.userId!` for tenant data.
- Schema change: edit `apps/central-api/prisma/schema.prisma` (PascalCase model, camelCase fields, `@@map("snake_plural")`) and add a migration under `apps/central-api/prisma/migrations/` (`pnpm --filter central-api db:migrate`).
- Tests: `apps/central-api/src/<feature>/<feature>.test.ts` using `buildApp()` + `app.inject()` against a `*_test` database.

**New control-plane endpoint:**
- Pure central passthrough: add to an existing `register*Routes` using `criarRepasse` (`apps/control-plane/src/central/repasse.ts`), guard `{ preHandler: app.requireSession({ precisaCentral: true }) }`.
- Local capability: `apps/control-plane/src/<feature>/routes.ts` exporting `register<Feature>Routes(app, deps)` with a typed `<Feature>Deps` interface; wire in `apps/control-plane/src/app.ts`.
- New Docker operation: extend `ContainerOrchestrator` in `apps/control-plane/src/orchestrator/types.ts`, implement in `DockerOrchestrator`, and update fakes in tests.
- New background loop/service: class in its own folder, constructed in `buildApp`, started in `apps/control-plane/src/server.ts`, stopped in the `onClose` hook.
- Tests: co-located `routes.test.ts` using `buildApp({ orchestrator: fake, dataDir: tmp, centralApiUrl: stub })`.

**New UI page/feature:**
- Authenticated page: `apps/web/app/(painel)/<route>/page.tsx` that only renders a component (pattern: `export const instant = false;` + `<Component />`); add a nav entry to `LINKS` in `apps/web/app/(painel)/layout.tsx` (`soAdmin` for admin-only).
- Component: `apps/web/components/<PascalName>.tsx` with `"use client"`, read session via `use(SessaoContext)`, call the backend with `apiFetch`/`apiUrl` from `apps/web/lib/api.ts` (paths relative to `/cp`).
- Types for API payloads: add to `apps/web/lib/api.ts` (mirrors control-plane/central responses).
- Pure logic (validation, formatting, merging): `apps/web/lib/<topic>.ts` + `apps/web/lib/<topic>.test.ts`.
- Before touching Next APIs read `apps/web/AGENTS.md` (Next 16 differs from older versions).

**New worker behaviour:**
- Bot action: add an `Acao<ClienteJogo>` in `criarAcoes()` in `packages/worker/src/game/loop.ts`.
- New game protocol message/endpoint: `packages/worker/src/game/client.ts` (extend `EstadoJogo` / `ClienteJogo`) and document it in `packages/worker/GAME.md`.
- New login strategy: implement `TokenProvider` in `packages/worker/src/auth/` and plug into `AuthManager` / `criarAuthManager()` in `packages/worker/src/auth/provider.ts`.
- New env var: parse and validate in `loadConfig()` (`packages/worker/src/config.ts`), add to `WorkerConfig`, and pass it from `montarEnv()` in `apps/control-plane/src/workers/routes.ts`.
- Tests: co-located `*.test.ts`; fixtures in `packages/worker/src/auth/__fixtures__/`.

**New deployable image:**
- Dockerfile: `docker/Dockerfile.<name>` following the 3-stage pattern with `ARG VERSION` → `ENV APP_VERSION`.
- Release: add `<name>` to the `matrix.imagem` list and the channel-retag loop in `.github/workflows/release.yml`.
- E2E: add build to `e2e/docker.ts` and service to `e2e/docker-compose.e2e.yml`.

**Utilities:**
- There is no shared cross-package library; each package owns its helpers. Worker HTTP helpers: `packages/worker/src/http.ts`. Control-plane central helper: `apps/control-plane/src/central/repasse.ts`. Recreation helpers: `apps/control-plane/src/orchestrator/recriar.ts`. Duplicated small helpers (e.g. `repositorioDaImagem` in both `apps/control-plane/src/orchestrator/orchestrator.ts` and `packages/updater/src/recriacao.ts`) are intentional because images are built per package (Dockerfiles copy only one package).

## Special Directories

**`apps/central-api/prisma/migrations/`:**
- Purpose: Prisma SQL migrations applied by `prisma migrate deploy` at container start and in CI.
- Generated: Yes (by `prisma migrate dev`), then reviewed.
- Committed: Yes

**`packages/worker/src/auth/__fixtures__/`:**
- Purpose: Captured game login HTML and JS chunk + fake JWT builder for solver/auth tests.
- Generated: No (captured manually)
- Committed: Yes

**`e2e/.estado/`:**
- Purpose: E2E runtime state (`workers.txt` of created worker ids for teardown) and Playwright `resultados/` output.
- Generated: Yes
- Committed: No (`.gitignore`)

**`dist/`, `.next/`, `node_modules/`:**
- Purpose: Build outputs (`tsc` → `dist/`, Next → `.next/standalone`) and dependencies.
- Generated: Yes
- Committed: No (`.gitignore`, `.dockerignore`)

**`.planning/`:**
- Purpose: GSD planning artifacts (`ingest-manifest.yaml`, `codebase/` maps).
- Generated: Yes (GSD tooling)
- Committed: Yes (by the orchestrator)

**`docs/`:**
- Purpose: Design and plan documents.
- Generated: No
- Committed: Yes (excluded from Docker build context via `.dockerignore`)
